# Library in-text search and jump contract

`apps/mobile/features/library/textFind.ts` is pure, offline and React-free.

- Build `createTextFindIndex(bundle, language)` once per pinned immutable bundle revision and active language. It copies strings and IDs, not mutable parts. Rebuild when either changes; never silently search newly downloaded content behind an open reader.
- `searchTextFind(index, query, { maxResults? })` returns immutable `{ matches, truncated, queryTooLong }`. Results follow bundle occurrence order, then source order. Matches are literal and non-overlapping. Blank/combining-mark-only queries return no matches. There is no cross-occurrence matching, translation fallback, explanation search or synthetic session-context text search.
- Markdown uses the existing reader inline grammar through `parseMarkdownSource`. Visible labels and emphasis content are searchable; supported formatting delimiters and safe-link destinations are not. Unsupported markup remains literal exactly as in the inline renderer. The Library renders inline Markdown, not the separate optional block grammar.
- Normalization is Unicode NFKD, locale-independent lowercase, combining-mark removal, and whitespace collapse. This includes accented Latin transliteration, Armenian compatibility ligatures and case, Russian case (and diacritic folding, including ё/е and й/и). It does not transliterate between scripts or promise arbitrary linguistic case folding.
- For #276 persistence, store the Library environment alongside the target and verify it against the active controller before resolving; the pure bundle does not carry an environment. No migration to a new revision is implied. `PassageJump` in `features/live/PartList.tsx` is the transient rendering request after `resolveTextJump` succeeds: use `key: library:${target.liturgyPartId}`, active language, validated start/end and an incrementing `requestId`; `focus: true` is for an explicit user jump, not typing updates. Omit the request on dismissal or stale language/revision. It does not change live-follow position or send controls.
- Each `TextJumpTarget` preserves `liturgyId`, `revision`, `language`, `liturgyPartId`, `partId`, `occurrenceIndex` and source UTF-16 `[start,end)`. Do not address repeated parts by `partId` alone. Normalization expansions and decomposed diacritics map back to complete original source spans; a match across formatted runs can include intervening raw Markdown syntax in its source range. Rendering highlights must intersect these ranges with the Markdown source map, not print the raw substring as display text.
- `resolveTextJump(bundle, target, activeLanguage?)` returns `{ occurrenceIndex, start, end }` only for that exact revision, liturgy, occurrence, language and valid nonempty source range; otherwise `null`. Default language is the target's language; callers should pass the current active language to reject stale-language results. Revision mismatch never falls back to `partId` or current ordinal.
- Queries are capped at 512 source UTF-16 units before normalization (`queryTooLong` rather than a silently shortened query). Results default to 200, with a hard cap of 1000; nonfinite limits use the default and finite limits clamp to 1–1000. `truncated` means another distinct source-span match exists, not a total count. There is no arbitrary text-prefix truncation.
- Validated public bundles already cap total payload at 10 MiB, occurrence count at 20,000 and each translation at 1 MiB. Normalization is a single scan; sparse offset runs coalesce ordinary text, and search reuses normalized strings. Plain long text bypasses Markdown parsing/source-map allocation. Existing inline-parser worst-case behavior on long malformed Markdown is unchanged; this module does not claim a hard execution-time bound for that shared parser. Consumers should memoize the index and debounce query updates, and must not fetch to search.

Deterministic coverage: `npm test --prefix apps/mobile -- --runTestsByPath tests/library-text-find.test.ts`.
