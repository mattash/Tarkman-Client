Authorized scope: [#283](https://github.com/mattash/Tarkman-Client/issues/283). ## Decision summary

Keep Tarkman's existing design direction and React Native controls. Ship three bounded, dependency-free improvements: **web SegmentedControl keyboard navigation, web TextField error association, and truthful Today mixed-status rows/headings**. Do not migrate to UI SDK or redesign the reader toolbar. Use existing native-check issues [#284](https://github.com/mattash/Tarkman-Client/issues/284) and [#285](https://github.com/mattash/Tarkman-Client/issues/285) as validation dependencies. New app-wide ARIA and interaction proposals are not assumed to be covered by those issues; future implementers must reconcile ownership/scope before filing additional work.

The existing literary serif, Armenian assets, platform-sans controls, semantic burgundy light/dark palette and explicit recovery states remain the design. All reader actions stay visible, Live stays beside Back, and no overflow menu or pinned service title is introduced. This is refinement of the incumbent application, not a new design world.

These implemented selections prioritize breadth of benefit, low domain risk and testability over an unassessed dependency migration. They add no package, token/palette change, navigation migration or business/controller rewrite. Verified scope is the tests and browser checks recorded below; native runtime is still unverified.

### A. SegmentedControl: local web keyboard behavior (T283-01)

**Scope:** [SegmentedControl](../../apps/mobile/components/SegmentedControl.tsx); [focused tests](../../apps/mobile/tests/segmented-control.test.tsx). Keep native radio/touch behavior and existing stacked layout. Web-only refs, tabIndex and key handling let selected option be the entry point; arrows move focus/select, Home/End reach endpoints, controlled value remains caller-owned.

**Benefit:** fixes an interaction shared by Services/library/appearance/size controls without maintaining a second component framework. **Trade-off:** local code now owns roving-focus correctness, RTL/layout choices and regression tests. Current patch uses orientation-specific arrows (Left/Right horizontal, Up/Down stacked) plus Home/End, not the SDK reference's both-axis radio behavior. This deliberate local contract is not full SDK parity; observed browser checks and unit-only cases are distinguished below. There is currently group-wide disabled state, not a per-option-disabled API; disabled-option skipping is a requirement only if that API is later added.

**Acceptance:** keyboard enters once, selection and focused option agree after controlled rerenders, wrapping is deterministic, modifier shortcuts are not hijacked, handled keys do not scroll the page, disabled group cannot interact, Tab/Shift+Tab can leave. Test empty/missing controlled value and narrow/large-text/RTL cases. Existing inappropriate aria-selected remains explicitly deferred under T283-05.

### B. TextField: explicit web invalid/error relation (T283-04)

**Scope:** [TextField](../../apps/mobile/components/TextField.tsx); [primitive tests](../../apps/mobile/tests/primitives.test.tsx). Generate a stable unique error ID, expose it on error text, and connect it through web aria-describedby/aria-invalid. Keep the accessible name, native hint, keyboard/autofill and visual focus behavior.

**Benefit:** a revisited invalid field carries its error context instead of relying solely on alert timing. **Trade-off:** RNW DOM translation and caller-prop precedence require testing. The optional web `aria-describedby` prop is merged with the error ID and retained after error removal, covered by regression tests. Native hint/name/keyboard behavior stays unchanged. Correcting association does not fix stale caller validation.

**Acceptance:** visible error has matching unique ID, invalid input references it, multiple fields do not cross-reference, custom accessibilityLabel survives, clearing error removes stale error relation, caller descriptions are not silently lost. Inspect actual Expo-web DOM/accessibility tree; test native hint/name preservation separately, without claiming a listening pass.

### C. Today: truthful Live and neutral mixed heading (T283-03)

**Scope:** [Today](../../apps/mobile/features/home/Today.tsx#L75-L82); [home UI tests](../../apps/mobile/tests/home-ui.test.tsx). Set visual live state and accessible row wording only for status `active`. Use current neutral Services translation for mixed/non-active secondary sections; keep existing live heading when all rows are active.

**Benefit:** removes a misleading service-state promise for sighted and screen-reader users. **Trade-off:** neutral grouping is less promotional but more accurate; this does not add a new paused badge to every secondary row or redefine backend discovery. Preserve lead-card status, existing row destination, onboarding and account-free access.

**Acceptance:** all-active rows retain Live; paused/ended/unknown are never announced Live; mixed heading is neutral both with and without lead; active-only headings remain localized; selecting a row opens the same service. Use a deterministic mixed fixture rather than waiting for real production services.

## 6. UI SDK: suitability by platform, not branding

UI SDK is an unstyled behavior/compound-component toolkit, not a React Native design kit or a replacement visual system. The [React installation source](https://github.com/vercel-labs/ui/blob/b16845af546eed32c87ec7fc871951557f966326/apps/docs/content/docs/react/installation.mdx) requires React and React DOM ≥19, component-subpath imports and a shared core instance. The app's React declarations satisfy only that peer prerequisite—not Expo Metro/export compatibility. The [mobile guide](https://github.com/vercel-labs/ui/blob/b16845af546eed32c87ec7fc871951557f966326/apps/docs/content/docs/core/mobile.mdx) discusses **mobile browsers**, DOM/visual viewport/CSS safe areas; it is not evidence of UIKit/Hermes/RN support.

Used the repository's actual [ui-sdk skill](https://github.com/vercel-labs/ui/blob/b16845af546eed32c87ec7fc871951557f966326/packages/core/skills/ui-sdk/SKILL.md), its build-interface/create-component/testing/agent-ready references, source React docs index, segmented-control/dialog/field/popups/mobile docs and manifests/changelogs. The skill calls for installed docs first; no SDK is installed and the source checkout has no generated `docs/llms.txt`. Used source MDX instead, not compiled JS or a validated npm tarball. Fetched the two pinned sources using `gh repo clone pbakaus/impeccable <isolated-path> -- --depth=1` and `gh repo clone vercel-labs/ui <isolated-path> -- --depth=1` (exit 0); recorded pins with `git rev-parse HEAD`. No runtime SDK install was needed for assessment, and the skill's web-install path was not interpreted as native adoption authority.

| Surface / contract | Native RN / iOS / Android | Expo web | Decision |
|---|---|---|---|
| Buttons, Back, headers/service rows | Keep Pressable, platform targets and native accessibility. | DOM behavior is possible but requires route/ref/style integration. | Keep local; fix role-state ARIA independently. |
| TextField / password / multiline | Keep TextInput keyboard, autofill, selection and IME behavior. | SDK Field/Input could supply relations but requires separate hosts/CSS. | Local error association now; no migration. |
| Segmented/radio choice | Keep native scalable roles/touch/layout. | Best small candidate; named group, one entry stop, checked state and keyboard control. | Local fix now; optional approved isolated web spike later. |
| Language/multi-choice rows | Distinguish checkbox, exclusive radio and immediate action. | Same semantics; not every choice is a listbox. | Keep; use correct checked/pressed contract. |
| Tabs / routes / LinkEditor steps | Expo history/deep links/native tabs remain authoritative. | Router links or full tab/panel contract must be deliberately chosen. | No SDK navigation migration. |
| AppModal / destructive confirmation | Preserve pageSheet/swipe, Android Back, safe areas, lifecycle and controller safeguards. | Dialog/Drawer may help naming, focus/inertness, Escape/return; browser matrix still required. | Keep native; broadest-risk web candidate, not first adoption. |
| Anchored status/presence popup | Keep RN presentation; shared geometry/focus helper possible. | Popover is appropriate for interactive retry; not Tooltip. SDK offers collision/dismissal contracts. | Local bounds fix first; optional later web popup spike. |
| Tour / reader find / live list | Native gestures, FlashList, follow/manual state and reader engine are app-owned. | Find is input/results/actions, not automatically Combobox/Command. | Keep domain behavior; borrow focus/dismissal test principles. |
| Static typography, status, surface, icon, projector | Preserve Armenian/literary type, semantic roles and platform presentation. | No behavior-library value for wrapping static content. | Keep; no optional CSS reset or palette replacement. |

### Stability, bundle and ownership unknowns

- **Beta/API risk:** core/React are beta.3, not stable 1.x. [React changelog](https://github.com/vercel-labs/ui/blob/b16845af546eed32c87ec7fc871951557f966326/packages/react/CHANGELOG.md) includes beta fixes for disabled navigation/server labels/server rendering; [core changelog](https://github.com/vercel-labs/ui/blob/b16845af546eed32c87ec7fc871951557f966326/packages/core/CHANGELOG.md) includes nested-modal inertness and restored-selection fixes. These are relevant change classes, not proof the current release is broken. A spike must pin matching versions and re-characterize upgrades.
- **Bundle delta unknown:** [React manifest](https://github.com/vercel-labs/ui/blob/b16845af546eed32c87ec7fc871951557f966326/packages/react/package.json) declares subpaths and sideEffects false; [core manifest](https://github.com/vercel-labs/ui/blob/b16845af546eed32c87ec7fc871951557f966326/packages/core/package.json) has no runtime dependencies. This permits tree-shaking, not a zero-cost or measured-size claim. No installation, production bundle comparison or native leakage inspection was performed by the researcher.
- **Maintenance trade:** centralized web keyboard/focus/dismissal behavior versus parallel RN/DOM implementations, CSS/token parity, ref contracts and separate test environments. NativeWind/Tailwind, font loading, scale, safe areas and navigation remain app responsibilities. Define an owner before adopting.
- **Browser support unknown:** [application README](../../apps/mobile/README.md) does not define a minimum web browser matrix. Browser top-layer support, Safari/mobile keyboard viewport and fallback need evaluation. Native iOS minimum is not browser compatibility evidence.
- **Agent features are out of scope:** SDK snapshots only see participating controls and agent changes may bypass click handlers. Do not add createAgent/WebMCP for an accessibility fix; any future use must preserve authorization, validation and destructive confirmations.

**Adoption verdict:** do not add UI SDK in #283. If separately authorized, test one noncritical `.web.tsx` control in a disposable spike. Compare identical baseline/patch production exports for route/shared JS, compressed transfer and CSS; inspect native bundles for SDK leakage; test actual supported browsers, focus/keyboard and styling parity before recommending production use.
